# Requirements Document

## Introduction

This feature converts the existing production web application "OnlySplit" into a cross-platform application that runs on web, Android, and iOS from a single React codebase. The conversion is performed in-place on the current Vite + React 19 + Tailwind CSS 4 project using Capacitor as the native runtime bridge. The existing UI, routing (HashRouter), authentication flows, API integrations (Axios with cookie-based refresh), and third-party integrations (Razorpay checkout) must be preserved without rewrite. The work also introduces Progressive Web App (PWA) capabilities, native app icons and splash screens derived from existing branding assets, and documented build workflows for producing web bundles, Android packages (APK/AAB), and iOS builds.

The objective is a single codebase that targets three platforms with minimal platform-specific code.

## Glossary

- **OnlySplit_App**: The existing React web application being converted to cross-platform, located at the repository root.
- **Capacitor_Runtime**: The Capacitor framework (core, CLI, and platform packages) that wraps the web build in a native WebView container for Android and iOS.
- **Web_Build**: The static asset bundle produced by `vite build` into the `dist` directory.
- **Android_Project**: The native Android project generated by Capacitor under the `android` directory.
- **iOS_Project**: The native iOS project generated by Capacitor under the `ios` directory.
- **Capacitor_Config**: The Capacitor configuration file (`capacitor.config.json` or `capacitor.config.ts`) at the repository root defining app id, app name, and web directory.
- **App_Display_Name**: The user-facing application name, "OnlySplit".
- **Package_Id**: The reverse-DNS application identifier, `com.onlysplit.app`, used for both Android and iOS.
- **PWA_Manifest**: The web app manifest (`manifest.webmanifest` or `manifest.json`) describing the installable web application.
- **Service_Worker**: The script that enables PWA offline caching and installability for the web target.
- **API_Client**: The Axios instance in `src/api/client.js` that communicates with the backend at `https://api-split.onlylabs.in/api` using `withCredentials: true` and cookie-based token refresh.
- **Razorpay_Checkout**: The Razorpay payment checkout SDK loaded via the external CDN script `https://checkout.razorpay.com/v1/checkout.js`.
- **Branding_Asset**: An existing image used for app identity, specifically `public/logo.png` and `src/assets/hero.png`.
- **Developer**: A person who builds, runs, or releases the OnlySplit_App.
- **Cap_Sync**: The `npx cap sync` operation that copies the Web_Build into the native projects and updates native dependencies.

## Requirements

### Requirement 1: Preserve Existing Vite Project Structure

**User Story:** As a Developer, I want the existing Vite project structure preserved during conversion, so that the current web application continues to build and run without regression.

#### Acceptance Criteria

1. THE OnlySplit_App SHALL retain the existing `src` directory layout, including `api`, `components`, `pages`, `services`, `store`, `routes`, `guards`, `hooks`, `layouts`, `providers`, `socket`, `constants`, and `utils` subdirectories.
2. THE OnlySplit_App SHALL retain the existing `index.html`, `main.jsx`, `App.jsx`, and `index.css` entry files without functional change to application rendering.
3. THE Web_Build SHALL continue to output to the `dist` directory.
4. WHEN `vite build` is executed after conversion, THE OnlySplit_App SHALL produce a Web_Build with the same application routes and pages available before conversion.
5. THE OnlySplit_App SHALL retain the existing Tailwind CSS 4, PostCSS, and ESLint configuration files.

### Requirement 2: Install and Configure Capacitor

**User Story:** As a Developer, I want Capacitor installed and configured in the existing codebase, so that the web application can run inside a native container.

#### Acceptance Criteria

1. THE OnlySplit_App SHALL include the Capacitor core, CLI, Android, and iOS packages as declared dependencies in `package.json`.
2. THE Capacitor_Config SHALL set the application id to `com.onlysplit.app`.
3. THE Capacitor_Config SHALL set the application name to `OnlySplit`.
4. THE Capacitor_Config SHALL set the web asset directory to `dist`.
5. WHEN Capacitor packages are installed, THE OnlySplit_App SHALL retain all existing dependencies and their declared version ranges.

### Requirement 3: Generate Android and iOS Native Projects

**User Story:** As a Developer, I want native Android and iOS projects generated, so that I can build and run the application on mobile devices.

#### Acceptance Criteria

1. WHEN the Android platform is added, THE Capacitor_Runtime SHALL create an Android_Project under the `android` directory.
2. WHEN the iOS platform is added, THE Capacitor_Runtime SHALL create an iOS_Project under the `ios` directory.
3. THE Android_Project SHALL be configured with the Package_Id `com.onlysplit.app`.
4. THE iOS_Project SHALL be configured with the Package_Id `com.onlysplit.app`.
5. THE Android_Project SHALL display the App_Display_Name "OnlySplit" as the application label.
6. THE iOS_Project SHALL display the App_Display_Name "OnlySplit" as the application label.

### Requirement 4: Preserve Application Functionality and Styling

**User Story:** As a Developer, I want all existing functionality, authentication, API integrations, and styling preserved, so that users experience identical behavior across platforms.

#### Acceptance Criteria

1. THE OnlySplit_App SHALL preserve all existing pages and feature flows present before conversion.
2. THE API_Client SHALL continue to use the base URL `https://api-split.onlylabs.in/api`.
3. WHEN the OnlySplit_App runs inside the Capacitor_Runtime, THE API_Client SHALL successfully complete authenticated requests to the backend.
4. WHEN a backend response returns HTTP 401 on a non-auth route, THE API_Client SHALL attempt the cookie-based token refresh flow and retry the original request.
5. IF the token refresh fails, THEN THE API_Client SHALL redirect the user to the login route using the HashRouter hash format.
6. THE OnlySplit_App SHALL render the existing Tailwind CSS 4 styling without visual regression across web, Android_Project, and iOS_Project.
7. WHERE Razorpay_Checkout is invoked, THE OnlySplit_App SHALL load the Razorpay_Checkout SDK and present the checkout interface.

### Requirement 5: Ensure Routing Works Inside Capacitor

**User Story:** As a Developer, I want React Router to work correctly inside the native container, so that navigation behaves identically on all platforms.

#### Acceptance Criteria

1. THE OnlySplit_App SHALL continue to use HashRouter for client-side routing.
2. WHEN the OnlySplit_App loads inside the Capacitor_Runtime from the `capacitor://` or `https://localhost` origin, THE OnlySplit_App SHALL render the default route without a blank screen.
3. WHEN a user navigates between routes inside the Capacitor_Runtime, THE OnlySplit_App SHALL display the target route content without a full page reload error.
4. WHEN a route redirect occurs via `window.location.hash`, THE OnlySplit_App SHALL navigate to the redirected route inside the Capacitor_Runtime.

### Requirement 6: Configure PWA Features

**User Story:** As a Developer, I want PWA features configured, so that the web target is installable and supports offline caching.

#### Acceptance Criteria

1. THE OnlySplit_App SHALL include a PWA_Manifest declaring the App_Display_Name "OnlySplit", a start URL, display mode, theme color, and background color.
2. THE PWA_Manifest SHALL reference application icons in at least 192x192 and 512x512 pixel sizes.
3. THE OnlySplit_App SHALL register a Service_Worker for the Web_Build.
4. WHEN the Web_Build is served over HTTPS and loaded in a supporting browser, THE OnlySplit_App SHALL present an installable PWA.
5. WHEN the Service_Worker is active and the network is unavailable, THE OnlySplit_App SHALL serve the cached application shell.

### Requirement 7: Add App Icons and Splash Screens

**User Story:** As a Developer, I want app icons and splash screens generated from existing branding, so that the native apps display consistent OnlySplit identity.

#### Acceptance Criteria

1. WHERE the Branding_Asset `public/logo.png` is available, THE OnlySplit_App SHALL use it as the source for generated app icons.
2. WHERE the Branding_Asset `src/assets/hero.png` is available, THE OnlySplit_App SHALL use it as the source for generated splash screens.
3. THE Android_Project SHALL include app icon assets in the required launcher icon densities.
4. THE iOS_Project SHALL include app icon assets in the required icon set sizes.
5. THE Android_Project SHALL include splash screen assets displayed at application launch.
6. THE iOS_Project SHALL include splash screen assets displayed at application launch.
7. IF a required Branding_Asset is absent, THEN THE OnlySplit_App SHALL report which asset is missing and continue the conversion without generating the corresponding icon or splash assets.

### Requirement 8: Set Up Build Workflows

**User Story:** As a Developer, I want production and development build workflows defined, so that I can build, sync, and run the application efficiently across targets.

#### Acceptance Criteria

1. THE OnlySplit_App SHALL provide an npm script that produces the Web_Build via `vite build`.
2. THE OnlySplit_App SHALL provide an npm script that runs the development web server via `vite`.
3. THE OnlySplit_App SHALL provide a documented command sequence that runs `vite build` followed by `npx cap sync` to update the Android_Project and iOS_Project with the latest Web_Build.
4. WHEN Cap_Sync is executed after a Web_Build, THE Capacitor_Runtime SHALL copy the `dist` contents into the Android_Project and iOS_Project.
5. WHERE a Developer needs live reload on a device during development, THE Capacitor_Config SHALL support a server URL configuration pointing to the Vite development server.

### Requirement 9: Document Native Build and Release Steps

**User Story:** As a Developer, I want documented native build and release steps, so that I can produce distributable Android and iOS artifacts.

#### Acceptance Criteria

1. THE OnlySplit_App SHALL provide documentation describing how to open the Android_Project in Android Studio.
2. THE OnlySplit_App SHALL provide documentation describing how to generate an Android APK artifact via Android Studio.
3. THE OnlySplit_App SHALL provide documentation describing how to generate an Android AAB artifact via Android Studio.
4. THE OnlySplit_App SHALL provide documentation describing how to open the iOS_Project in Xcode.
5. THE OnlySplit_App SHALL provide documentation describing how to build and archive the iOS_Project via Xcode.
6. THE documentation SHALL state the prerequisite tooling required for each platform build, including Android Studio for Android and Xcode on macOS for iOS.
